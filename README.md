# TerraTrace

Рабочий учебный прототип помощника для мододела. Загрузи client.log или server.log из tModLoader: программа найдёт ошибки и предупреждения, объединит повторы и покажет исходные строки вместе с подсказками.

## С чего начать

1. Распакуй архив в отдельную папку.
2. В редакторе открой папку **TerraTrace**, где находится main.py.
3. Запусти сервер по инструкции ниже.
4. Открой http://127.0.0.1:8000 и нажми **Попробовать демо**.
5. Открой **Как устроен проект**. Там есть кнопка-счётчик и кнопка, которая действительно обращается к Python.

Учебная страница: http://127.0.0.1:8000/guide  
Документация запросов: http://127.0.0.1:8000/docs

## Запуск на macOS

Нужен установленный Python 3.12 или новее. Открой терминал в папке с main.py:

~~~bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python -m uvicorn main:app --reload
~~~

После запуска терминал остаётся занят сервером. Его останавливают Control+C.

При следующем запуске заново устанавливать библиотеки не требуется:

~~~bash
source .venv/bin/activate
python -m uvicorn main:app --reload
~~~

## Запуск на Windows

PowerShell, в папке с main.py:

~~~powershell
py -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python -m uvicorn main:app --reload
~~~

Если PowerShell не разрешает активировать окружение, можно использовать его Python напрямую:

~~~powershell
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m uvicorn main:app --reload
~~~

## Запуск кнопкой в PyCharm

Выбери для проекта интерпретатор из его окружения и установи requirements.txt. Затем запусти **run.py** кнопкой Run. Этот файл запускает тот же Uvicorn на порту 8000.

В main.py описано приложение, а run.py — удобный отдельный способ его запустить. Не запускай одновременно run.py и сервер из терминала: они будут занимать один порт.

Если видишь «Address already in use», останови предыдущий сервер через Control+C. Либо для второго процесса выбери другой порт:

~~~bash
python -m uvicorn main:app --reload --port 8001
~~~

Тогда адрес страницы будет http://127.0.0.1:8001.

## Что уже работает

- Выбор и перетаскивание .log/.txt, вставка текста.
- Реальный Python-разбор демонстрационного журнала.
- Выделение ERROR, FATAL и WARN, многострочные исключения.
- Объединение повторяющихся событий со счётчиком.
- Семь диагностических правил: null, ресурсы, параметры эффектов, зависимости, версии API, память, формат библиотеки.
- Фильтр по уровню и упомянутому моду, поиск по тексту и стеку.
- Раскрываемые технические подробности.
- Скачивание TXT и JSON.
- Сохранение последних пяти отчётов в этом браузере по отдельной кнопке.
- Понятные ошибки для пустых, двоичных и слишком больших файлов.
- Страница обучения с двумя работающими примерами кнопок.
- Интерфейс для компьютера и телефона.

Журнал examples/boss_test.log синтетический. В нём 12 записей ошибок, собранных в три группы ошибок, и одно предупреждение: всего четыре группы.

examples/clean.log показывает вариант без записанных ошибок. examples/unknown_error.log — случай, для которого пока нет правила.

## Как разложен код

| Файл | Роль |
|---|---|
| main.py | Создаёт FastAPI, подключает роутеры, выдаёт HTML |
| run.py | Запускает сервер кнопкой Run |
| templates/index.html | Элементы основной страницы |
| templates/guide.html | Учебная страница |
| static/styles.css | Весь внешний вид и адаптация к телефону |
| static/app.js | События формы, запросы, отрисовка, фильтры, экспорт и история |
| static/guide.js | Два небольших учебных примера |
| routers/logs.py | HTTP-обработчики загрузки и анализа |
| services/log_parser.py | Разбор текста, маскирование, группировка и сводка |
| services/diagnostics.py | Список правил и функция diagnose |
| schemas/log_schema.py | Структура входящих и исходящих данных |
| security.py | SHA-256 для отпечатков событий |
| tests/ | Проверки разбора и API |

Твои заготовки routers/account.py и schemas/account_schema.py сохранены. Регистрация, вход и хранение аккаунтов пока не реализованы. SHA-256 из security.py используется для группировки ошибок и не подходит для хранения паролей.

Здесь обычные HTML/CSS/JavaScript. Node.js, сборщик frontend и отдельный сервер для страницы не нужны.

## Как проходит нажатие «Разобрать лог»

1. HTML содержит форму logForm и кнопку type="submit".
2. Браузер вызывает обработчик submit в static/app.js.
3. event.preventDefault() отменяет обычную перезагрузку страницы.
4. JavaScript помещает файл в FormData и вызывает fetch("/api/logs/analyze", ...).
5. FastAPI запускает analyze_uploaded_log() в routers/logs.py.
6. Роутер проверяет файл, читает байты и передаёт текст в analyze_log().
7. Сервис собирает события, группирует повторы и вызывает diagnose().
8. FastAPI превращает модели Pydantic в JSON.
9. JavaScript получает результат. renderReport() и filterGroups() обновляют страницу.

Роутер знает про HTTP. Сервис работает с текстом и не импортирует приложение из main.py.

## Где добавлять визуал и поведение

**Новая надпись или кнопка:** templates/index.html.  
**Цвет, размер, отступ:** static/styles.css.  
**Реакция на нажатие:** static/app.js.  
**Новый адрес сервера:** routers/logs.py.  
**Новый алгоритм:** services/log_parser.py или отдельный файл services/.  
**Новая подсказка:** список RULES в services/diagnostics.py.

Начни с четырёх маленьких изменений:

1. Поменяй заголовок страницы в HTML и обнови браузер.
2. Измени background у .button-primary в CSS.
3. Измени текст учебной кнопки в static/guide.js.
4. Добавь правило для MY_TEST_ERROR по примеру на странице /guide.

Подробное объяснение и пример новой кнопки с запросом к серверу: **docs/LEARNING.md**.

После изменения HTML, CSS и JS обновляй страницу. После изменения Python-файлов сервер с --reload перезапускается сам.

## API

| Метод и адрес | Что происходит |
|---|---|
| GET / | HTML основной страницы |
| GET /guide | Учебная страница |
| GET /api/health | Проверка связи с сервером |
| POST /api/logs/analyze | Анализ одного файла, поле формы file |
| POST /api/logs/text | Анализ JSON с полем text |
| GET /api/logs/demo | Разбор учебного журнала тем же анализатором |
| GET /api/logs/example | Скачать пример журнала |
| GET /docs | Интерактивная документация API |

Для загрузки используй поле **file**. В JSON-запросе к /api/logs/text:

~~~json
{"text": "ERROR: MY_TEST_ERROR"}
~~~

## Границы прототипа

- Сначала поддерживаются типичные заголовки tModLoader и текстовые ERROR:/WARN:. Все варианты формата разных версий ещё не проверены.
- Лимиты: 5 МиБ, 50 000 строк, 32 000 символов в строке. В отчёте максимум 200 групп; если их больше, появится пояснение.
- Подсказки основаны на текстовых правилах. Упоминание мода не доказывает, что он вызвал ошибку.
- Неверное поведение босса без диагностических записей нельзя определить по отсутствующему сообщению.
- Типовые имена в путях, IPv4, email и некоторые поля с секретами заменяются масками. Полной анонимности это не гарантирует: проверь отчёт перед передачей.
- История хранится в браузере; очищается кнопкой «Очистить историю». Сервер не ведёт базу отчётов и не сохраняет исходные журналы в проект.
- Это локальный учебный прототип. База данных, аккаунты и ML — следующие отдельные этапы.

## Проверки

Для тестов дополнительно нужен httpx:

~~~bash
python -m pip install -r requirements-dev.txt
python -m unittest discover -s tests -v
~~~

Тесты проверяют многострочный стек, повторы, разные ресурсы, неизвестные ошибки, кодировки, маскирование, ограничения и HTTP-запросы к приложению через ASGI. Дополнительно проверены синтаксис JavaScript и соответствие id элементов обработчикам. Полная проверка в браузере этой среды была недоступна; перед дальнейшей разработкой пройди ручную проверку ниже на своём компьютере.

### Ручная проверка интерфейса

1. Нажми «Попробовать демо»: ожидаются 12 ошибок, одно предупреждение и четыре группы.
2. Выбери предупреждения: должна остаться карточка параметра эффекта.
3. Введи несуществующее слово в поиск: появится сообщение об отсутствии результатов.
4. Сбрось фильтры и скачай TXT и JSON. Открой файлы и проверь содержимое.
5. Сохрани отчёт в историю, обнови страницу и открой его снова.
6. Загрузи examples/clean.log: счётчик ошибок должен стать нулевым.
7. На /guide нажми обе учебные кнопки и посмотри результаты.
8. Уменьши ширину окна: блоки должны перестроиться без горизонтального прокручивания всей страницы.

При разработке использовались Python 3.12, FastAPI 0.141.1, Uvicorn 0.52.1, Pydantic 2.13.4, python-multipart 0.0.32 и httpx 0.28.1. requirements.txt содержит совместимые диапазоны прямых зависимостей. После своей установки можно записать фактически установленные версии:

~~~bash
python -m pip freeze > requirements-lock.txt
~~~
